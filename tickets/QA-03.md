# QA-03 — Validate the status query parameter

GOAL: `/api/metrics` rejects unknown status values with HTTP 400 and a helpful
error body, instead of silently returning an empty list.

CONTEXT: `api/app.js`. Valid statuses: all, on-track, at-risk, blocked, done.

CONSTRAINTS:
- Error body shape: `{ "error": "invalid status", "allowed": [...] }`.
- Existing valid-status behavior must not change.

ACCEPTANCE CRITERIA:
- [ ] `?status=bogus` returns 400 with the specified body.
- [ ] All valid statuses still return 200 with filtered items.
- [ ] Integration tests cover both paths.

VERIFY WITH: `npm test`
